## Fixed today (bug fixes, tests first)

1. **The earnings fix of 21 Oct never reached the trading jobs.** The hourly jobs restore data/news from GitHub's
   cache, which still holds the earnings calendars as first downloaded on 30 Sep, and it overwrote the refreshed
   files from the repo. So the accounts' event blackout has kept using the old dates (META listed for 28 Oct).
   **Correction to yesterday's report:** the accounts did not buy META before its report, but not because of the
   fix: no META entry signal passed their filters. Fix: right after the cache is restored, every job (data, A-F,
   engine) takes the earnings files from the repo again. The same stale file made the morning engine run fail at
   its last step (a git conflict saving its log; shadow only, nothing traded).
2. **C's AMZN sell missed the opening auction.** AMZN was already below C's opening-range stop before the open, so
   the 9:05 run queued an auction sell. The 9:12 and 9:20 runs each cancelled it and sent it again (the "already
   queued" check did not apply in the auction window); the last copy went out at 9:26, two minutes before
   Alpaca's 9:28 cut-off, and expired unfilled. The shares were sold by the 9:50 run at 9:57. Fix: in the auction
   window, orders that already match the plan are left alone, and auction orders stop at 9:25 (a plain market
   order sent later still fills at the open).
3. **F: Alpaca vs book.** F's status now lists every leg Alpaca holds next to the book: quantity, Alpaca's value
   and the value at the quotes' mid, flagging legs the book does not know and prices far from the quotes.
   Reporting only, no trade depends on it.
