## Fixed today

- **C's book lost two trades it had made.** On Friday 30 Oct the morning earnings refresh dropped XOM's report
  date (that very day: the download left it out), so C's event blackout did not see the report and C bought XOM
  twice at 14:00 UTC. Both were stopped at this morning's open (-$400, -$339). This morning's refresh put the
  date back, and from the 15:58 UTC run C's replay applied the corrected calendar to the past: the two trades
  vanished from its book, which then showed about $740 more than C's Alpaca account had made.
  - Fixes (tests first): a refresh no longer drops a report date on or before today (future dates still follow
    the download); C's replay now reuses the event blackout each live run used (paper/C/blackout.json), as it
    already reuses the learner's decisions, so a revised calendar can no longer rewrite trades already made.
  - Regression check (offline: cached prices and news, no Alpaca keys): with the calendar the live runs had, the
    replay gives C's book of 15:27 UTC exactly (68 trades: same quantities, prices, P&L, positions); with the
    stored blackout and today's calendar, the same 68 trades; without it, the rewrite of 15:58 exactly (66).
- **A wrong event blackout sold C's positions at the close.** The "flat at the last bar of the session before an
  event" rule took the newest day in the data for that session whenever the event was at most 4 days away: on
  Monday, the jobs report of Friday 6 Nov blacked out every stock's 15:00 bar, C's 20:23 UTC run went flat on
  Alpaca (TSLA, TLT sold), and the next run, with Tuesday in the data, held them again and queued buys for
  Tuesday's open. It would have happened again on Tuesday and Wednesday.
  - Fix (test first): a later event waits for the session right before it (no market day in between; NYSE
    holidays counted).
  - C's blackout record keeps Monday's 15:00 bar as the live run used it, so its book closes the positions like
    its Alpaca account did; the 23:26 run cancelled the queued TLT and TSLA buys and queued only XOM. **Alpaca
    and the book agree again** ("Alpaca matches the plan").
  - Regression check: on the full price history of C's universe the old and new rule give the same blackout for
    every bar, so no replayed decision changes. Replaying each session as the live run saw it, the old rule also
    blacked out the last bar falsely on 8 earlier days since 30 Sep (19 assets on 30 Sep, 1-5 on the others):
    when C held one of those stocks, Alpaca sold it at the close and bought it back the next morning while the
    book held it, one of the reasons C's book and its Alpaca account can differ.
